# Public demo audio

Only place audio here when Vocal Studio owns it or has explicit permission to distribute it publicly.
Do not copy files from `storage/uploads`, `storage/outputs`, model folders, or user workspaces here.
Never put model checkpoints, credentials, or private recordings under `public`.

Keep samples short and reasonably small (prefer 10 MB or less each). Use clear labels and, for
voice-conversion samples, confirm that the original and converted files are a genuine matching pair
and that both the voice model and recordings may be redistributed.

The TTS gallery includes a short sample generated by the configured `en_US-lessac-medium` Piper voice.
Its source sentence and model are identified in the gallery. The separation stems were produced by an
actual Demucs job using that speech sample; they are clearly labeled as speech stems, not music stems.
The voice-conversion pair uses the same Piper source and an actual RVC job with `default.pth`. Voice
Lab shows only the Piper preview and explicitly does not claim it is a Voice Lab processing result.

## Folders

- `separation/`: spoken Piper source, matching Demucs vocal stem, and matching Demucs instrumental stem.
- `tts/`: a genuine sample generated with the named Piper voice and an approved sentence.
- `voice-conversion/`: a matching original/converted pair, with the authorized model name and category.
- `voice-lab/`: genuine preview and processing example files; do not label a preview as processing.

## Enabling a sample

1. Add the permitted, compressed audio file(s) under the corresponding folder.
2. Add a sample object to the relevant `SAMPLE_CATEGORIES` entry in
   `frontend/src/pages/DemoGallery.jsx`, supplying the exact `/demos/...` public URL, visible title,
   and any required attribution/model metadata.
3. `SampleCard` enables its player only when the authored sample URL starts with `/demos/`; add a
   download label only when the file is approved for download.
4. Run `npm run build` and verify each sample URL returns HTTP 200 and plays in a browser.

The prepared TTS sample is distinct from live TTS, which sends text to the configured backend only
after the visitor presses **Generate with Piper**.
